# Contributing to Roofwright

Thanks for helping. Issues, ideas and pull requests are all welcome. Please follow the
[Code of Conduct](CODE_OF_CONDUCT.md), and report security problems privately as described in
[SECURITY.md](SECURITY.md).

## Setup

- JDK 25 (any distribution). Gradle comes with the wrapper.
- No Minecraft account is needed: Loom downloads the game for development.

```bash
./gradlew build              # compile + unit tests + server GameTests
./gradlew benchmark          # planner benchmark, footprints from 16x16 to 256x256
./gradlew runServer          # dev server in ./run
./gradlew runClient          # dev client (offline account)
./gradlew runClientGameTest  # real client; regenerates screenshots, opens a window
```

## Layout

| Path | What lives there |
|---|---|
| `src/main/java/.../core` | Pure logic with no Minecraft classes: outline detection, the roof planner (distance fields, wings, profiles, pieces), vanilla's stair corner rule, undo history, settings. Unit tested. |
| `src/main/java/...` | Thin Minecraft layer: commands, wand, materials from block families, protection checks, tick-spread placement with undo and redo, the packet-only preview. |
| `src/test` | JUnit tests for `core` and config loading, and the planner benchmark. |
| `src/gametest` | Server GameTests (`RoofwrightGameTests`) and the client capture (`client/RoofwrightCaptures`). Macaw's Roofs is on this classpath only, to test its blocks as material. |
| `tools/` | `benchmark.sh` (placement on a dev server over RCON), `rcon.py`, `mutation.py` (the mutation check). |
| `docs/` | Research report and its verification, specification, gate log, reviews. |
| `site/` | GitHub Pages site. `branding/` holds the artwork scripts and the CurseForge copy. |

## Rules for changes

- **Every behaviour change comes with a test that would fail without it.** Prefer `core` unit tests;
  use a GameTest when real blocks, commands, permissions or protection are involved.
- **Roof shapes:** run the property tests (`everyRoofIsWatertight`, `everyStairHasTheShapeVanillaWouldGiveIt`)
  and look at a real capture before and after. A shape that passes the tests can still look wrong.
- **Mutation check:** `python3 -P tools/mutation.py` plants 38 mutants and fails unless a named test
  kills each one. Add a mutant when you add a safety rule.
- **Never overwrite without consent:** placement fills air only; anything else needs `force`, and
  block entities and unbreakable blocks are never replaced.
- **Performance:** placement runs on the server thread within `blocksPerTick` and `millisPerTick`.
  If you touch `PlacementJob` or the planner, include `./gradlew benchmark` or `tools/benchmark.sh`
  readings from before and after.
- **Server-side only:** no new blocks, items, packets or registries, so vanilla clients keep working.
- Code style: tabs, and match the surrounding code. Comments explain why, not what.

## Pull requests

1. Open an issue first for anything bigger than a bug fix, so we can agree on the approach.
2. Keep the PR focused, run `./gradlew build`, and fill in the template.
3. If roofs or chat output change, regenerate the media (see "Artwork" below) and update the chat
   line quoted in `site/index.html` and `branding/curseforge-description.md` from the same run's log.

## Artwork

Everything is generated by scripts, so it can be redone after any change:

| Script | Produces |
|---|---|
| `caffeinate -dimsu ./gradlew runClientGameTest` | Real client captures in `build/run/clientGameTest/screenshots` (macOS: `caffeinate` stops display sleep from stalling the window) |
| `branding/make_media.sh` | `site/media`: before and after, gallery, style grid, preview, chat crop, the roof-growing GIF, WebP versions |
| `Blender -b -P branding/render_logo3d.py -- branding/logo3d.png` | The 3D voxel logo, rendered from the icon's own pixels |
| `python3 -P branding/make_banners.py` | `banner.png`, `social.png`, `readme-header.png` |
| `python3 -P branding/make_icon.py` | The pixel icon at every size (mod icon, favicon, touch icon) |

## Releases (maintainers)

Roofwright is published on CurseForge. The one-time project setup (page, logo, gallery, token,
project ID) is in [`branding/curseforge-listing.md`](branding/curseforge-listing.md).

1. Move the `Unreleased` notes in `CHANGELOG.md` under the new version and set `version` in
   `gradle.properties` (`-alpha.N` / `-beta.N` / `-rc.N` suffixes pick the CurseForge release type).
2. Set `curseforge_project_id` in `gradle.properties` once the project exists, and the
   `CURSEFORGE_TOKEN` repository secret.
3. Tag `vX.Y.Z` and push the tag. The release workflow builds, runs every test, creates the GitHub
   release and uploads to CurseForge when the token is set.
4. `./gradlew publishCurseforge` without a token or project id is a dry run: it assembles the upload
   under `build/publishMods/` without sending anything.
