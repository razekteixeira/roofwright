# Security review: G5 Security clean

Reviewer: Security Agent (fresh context), 2026-10-09. Branch `roofwright-build` at `ae2f278` plus the
untracked README, CONTRIBUTING, CHANGELOG and branding scripts present in the worktree.

## Scope

- Sensitive tags from `docs/spec.md`: `world-modification`, `permissions`, `config`.
- Code: every file in `src/main/java` and `src/main/resources`; `src/gametest` only to confirm it does
  not ship or register production commands.
- Build and supply chain: `build.gradle`, `settings.gradle`, `gradle.properties`, Gradle wrapper,
  bundled jars, `.github/workflows/*.yml`, `tools/*`.
- Repository hygiene: secrets, personal emails and local paths in the working tree and in the full
  git history (all branches).

## Method

1. Read the spec, then all platform and core classes, tracing each entry point (the `/roof` tree, the
   `/roofwright` redirect, `UseBlockCallback`, `UseItemCallback`, `AttackBlockCallback`) to the block
   writes in `PlacementJob.apply` and the packets in `Preview`.
2. Threat models: a griefer who holds only `roofwright.use` (the README tells owners to grant it to
   builders through LuckPerms), a modified client, a malicious or broken config file, and a
   supply-chain attacker in CI.
3. Measured one suspected denial of service directly: `Footprint.Builder.addRectangle` from the
   compiled classes in `jshell` with a 2 GB heap (the code path `/roof select` runs before its span
   check). Results: 512 x 512 in 70 ms, 2,000 x 2,000 in 885 ms, 6,000 x 6,000 `OutOfMemoryError`
   after 16.4 s.
4. Checked the Common Protection API 2.0.0 surface with `javap` (`canPlaceBlock`, `canBreakBlock`,
   `canInteractBlock` and others) and the shipped jar's nested libraries
   (`META-INF/jars/common-protection-api-2.0.0.jar`, `fabric-permissions-api-0.7.0.jar` only; no
   GameTest classes, no Macaw's Roofs).
5. Tools: `actionlint` 1.7.12 on `.github/workflows`: exit 0, no findings. `shellcheck` 0.11.0 on
   `tools/*.sh`: exit 0, no findings.
6. Secrets: `git log -p --all` grepped for token, password, secret, API key, private key headers,
   `ghp_`, `github_pat_`, `sk-`; and for every email address. Only hits: workflow variable names, the
   per-run RCON password generator, the commit author `22983237+razekteixeira@users.noreply.github.com`,
   the `noreply@anthropic.com` co-author trailer and the upstream library author's public address in
   `THIRD_PARTY_NOTICES.md` (licence attribution). No remote branches exist yet, so nothing is pushed.

### Checked and clean

- Authorisation: `/roof` and the `/roofwright` redirect both require `roofwright.use`, and Brigadier re-checks child `requires` through a redirect; `force` and `reload` have their own nodes. Levels are read from the config on every check and command trees are resent after reload. Every wand callback builds a fresh command source and checks `roofwright.use` on each click, returning `PASS` (a plain stick) without it, so a creative player who forges the `custom_data` marker gains nothing. `place force` is the only path that sets `force`; undo and redo replay with an expected state per block.
- World safety: build height and world border are checked per block at plan time and again at placement; unloaded chunks are skipped at placement; without `force` only air is replaced; with `force`, block entities and unbreakable blocks are never replaced; claims are checked against the builder's `NameAndId` after logoff; undo and redo skip blocks changed since; jobs are one per owner and share one global per-tick budget (`blocksPerTick`, `millisPerTick`), with at least one block per call so nothing starves forever.
- Network: preview packets go only to the builder's connection; ghost ids come from the global entity counter and the entities are never added to a level, so they cannot collide, persist or be interacted with; bundles hold at most 4,000 packets (protocol limit 4,096); the server trusts nothing from the client beyond vanilla-validated click positions and the sneak flag.
- Config: fixed path under the config directory, no user-controlled paths, no reflection or code execution; lenient codec with defaults, every value clamped with a warning, an unreadable or invalid file keeps the previous settings and is never overwritten; only a missing file is created.
- CI: `build.yml` is read-only, `pages.yml` has the minimum Pages permissions; actionlint and shellcheck clean; the dev server in `tools/benchmark.sh` binds to 127.0.0.1 with a random RCON password per run, and `run/` is gitignored.
- Secrets and personal data: none found in the tree or history beyond the items listed under Method.

## Verdict

**Not clean.** H1 is a server crash or hang reachable by any holder of `roofwright.use`, the node the
README tells owners to hand to builders. The gate turns **clean with fixes** once H1, M1 and M2 are
fixed, each with a test that fails before the fix (H1: a far-apart `/roof select` is refused without
allocating; M1: forbidden materials and gable blocks are refused; M2: a burst of wand clicks runs at
most one detection per cooldown), and the build is re-verified. The low findings should be fixed or
recorded as accepted risks in `docs/sdlc-log.md`; L9 should be fixed before the first push.

Fixes by the delivery lead in a resumed session; every fix with a test that fails without it is also a
planted mutant in `tools/mutation.py` (M21 to M30), each killed by the test named in
